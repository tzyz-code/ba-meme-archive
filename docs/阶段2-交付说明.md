# 阶段 2 交付说明：后端骨架

## 交付内容

把阶段 1 的「纯前端原型」升级为「有后端、数据落库」的完整站点。

### 新增文件

| 文件 | 职责 |
|---|---|
| `server.js` | Express 服务：静态托管 + 搜索 API + 排序权重落地 |
| `db.js` | SQLite（Node 内置 `node:sqlite`，零编译依赖）+ 建表 + 查询 |
| `seed.js` | 种子脚本：从 `data.js`（单一数据源）把模拟数据落库 |
| `data/archive.db` | SQLite 数据库文件（WAL 模式） |
| `test-api.js` | API 回归验证脚本 |

### 数据库（4 张表）

- `ips` — IP 权重表（蔚蓝档案 weight=1.0）
- `characters` — 角色维度表（**出现即建目录**：新角色上传/识别时自动 INSERT）
- `emotions` — 情绪标签
- `memes` — 表情档案（emo 存 JSON 数组）

### API

| 端点 | 说明 |
|---|---|
| `GET /api/search?q=&ip=&char=&emo=&sort=&limit=&offset=` | 搜索，服务端执行排序权重 |
| `GET /api/chars` | 角色目录（按收录数降序） |
| `GET /api/meme/:code` | 单条详情 + 相关档案 |
| `GET /api/meta` | IP / 情绪 / 角色 元数据 |

### 排序权重（服务端落地）

```
最终分 = 文本相关性 + 0.35×IP权重 + 0.20×热度归一 + 0.15×时效归一 + 0.03×置信度
```

实测（`test-api.js` 8 项全过）：搜「白子」命中白子、搜「猫猫」命中通用表情、默认排序前 6 名全是蔚蓝档案、搜编号 BA-0003 精确命中、新角色 azusa 可检索、详情+相关正常。

### 前端接入方式

`data.js` 通过**同步 XHR** 在加载时拉取 `/api/meta` + `/api/search?limit=500`，成功后用后端数据、失败回退到内置静态兜底数据。页面脚本零改动。

> 说明：数据量小（几十条）时同步 XHR 最简；阶段 5 素材量大后改异步 fetch。

## 如何启动

```bash
cd meme-archive
npm install        # 首次
npm run seed       # 首次落库（可重复执行重置）
npm start          # 启动 http://localhost:3000
```
